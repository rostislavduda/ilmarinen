## v1.4.0 -- D1: singular MDL (fuse the LLC into the pricing as a functional code length)
- New module machinery/singular_mdl.py implementing direction D1 from directions_round2.md: it welds the two pieces the package had kept separate -- the STRUCTURAL contract code length (contract_mdl.omega_struct, a function of contract type) and the LOCAL LEARNING COEFFICIENT lambda (singular_complexity.estimate_llc, a geometric invariant of the fitted loss basin) -- via the singular-model MDL identity MDL_sing = -log p(D|w*) + lambda*log n + const (Urdshals, Lau, Hoogland, van Wingerden & Murfet, arXiv:2510.12077, 2025).
- Design stance: ADD, not replace. A premise check (fit the same rank-1 target with tanh nets of width H=2,8,32) confirmed the two terms price DIFFERENT axes: lambda/(k/2) collapses with width (0.360 -> 0.068 -> 0.017, the correct SLT singular signature) while omega_struct is width-blind (identical for all). So lambda*log n supplies FUNCTIONAL complexity -- the effective dimension of the realized fit -- that the structural code length cannot see. The total is Omega_total = omega_struct(contract) + omega_func(lambda, n), the two complementary rungs of the same J = R + mu*Omega ladder. This matches singular_complexity's own docstring note that the parametric-Occam term (which cancels across contracts at a shared budget) can be "reintroduced as lambda_c*log n, which does NOT cancel when contracts have different effective dimension."
- Public API (top-level ilmarinen): omega_func(lambda, n) = lambda*log n; total_code_length(lambda, n, contract, **struct_kwargs) = omega_struct + omega_func; singular_free_energy(residual_nll, lambda, n) = R + lambda*log n; and singular_complexity_of(model, loss_closure, n, ...) which estimates lambda at the (assumed converged) optimum and returns the priced functional code length WITH an explicit validity flag.
- Safety: everything is OPT-IN; no default objective changed. The guard from B2 is carried through -- a strongly-negative lambda_hat (a non-converged w*, since RLCT >= 0) is flagged valid=False and priced as NaN, so a garbage lambda can never enter the objective. Verified: converged linear fit -> valid, positive omega_func; 1-step (non-converged) fit -> valid=False, omega_func=NaN.
- Tests: added tests_unit/test_singular_mdl.py (7 fast identity/guard tests + 1 @smoke value test). The fast set locks the omega_func identity, the small-n guard, additivity total = struct + func, the reduction to structural when lambda=0, the singular-free-energy identity, the D1-CRITICAL guard-rejects-non-converged test, and the property that adding a fixed functional term preserves the set <= graph <= equivariant structural ordering. ## v1.8.1 -- D1 near-tied contract-flip study (when is the functional code length decision-relevant?)
- Study (not a package feature; new reproducer `studies/d1_contract_flip_study.py` + write-up `tests/d1_contract_flip.md`): resolves the open D1 question -- D1 was only ever shown to FIRE + GUARD on QM7-equiv, never to FLIP a contract decision. Asks whether ANY converged near-tied regime exists where the functional code length omega_func = max(lambda,0)*log n changes which contract is chosen.
- Construction of the structural near-tie: a COMPLETE graph has Omega_struct(graph) = E*log(P/E) -> 0 as E -> P = N(N-1)/2 (log 1 = 0), matching Omega_struct(set) = 0. On fully-connected relational data set and graph are structurally tied at ~0 nats, so only fit and functional complexity distinguish them. Target is a permutation-invariant first-moment statistic expressible by BOTH a mean-pool set encoder and a complete-graph encoder -> a tight fit tie. Both nets trained to convergence, lambda measured at the optimum by the real estimator, across 5 seeds x 4 prices mu_c in {0.05,0.1,0.2,0.4}.
- Result (first-class NEGATIVE with a precise mechanism): natural training NEVER flips the decision -- 0 flips across all seeds and prices, winner is `set` struct-only and struct+func alike. The reason is a structural ALIGNMENT of two Occam pressures: at a structure+fit tie the simpler class (set) simultaneously wins the structural tie-break (Omega=0) AND has the LOWER functional complexity (lower lambda, since it fits at least as well with fewer effective DoF; set lambda ~1.0-1.5 vs graph 1.5-2.0 every seed). So omega_func pushes the SAME direction as the structural verdict and can only reinforce, never overturn it -- in exactly the regime where it had most leverage.
- The MECHANISM can flip, but only in the ANTI-CORRELATED corner where the fit-leader is the MORE singular contract: placing lambda so the fit-leader (set) has lambda=8 vs graph lambda=1 flips set->graph at every price, threshold at mu_c=0.05 of fit-leader lambda >= 1.25 (a ~1.5-nat omega_func gap). So the term is real and correctly signed; it just needs fit-quality and functional-simplicity to be anti-correlated, which natural training here does not produce.
- Conclusion: omega_func honestly prices effective DoF and is correctly guarded, but is decision-relevant only when the fit-leader is the more singular contract -- a corner neither QM7-equiv (structural spread dominates) nor a structure+fit-tied regime (aligned Occam pressures) reaches. This BOUNDS D1's role: it refines J and reports effective DoF as a diagnostic, but does not change the chosen contract on realistic converged data. Explains WHY the fusion is safe (never fights the structural verdict naturally) while remaining theoretically complete (it would bite if the pressures decoupled).

## v2.1.0 -- CPU-vs-MPS performance routing audit (Apple-Silicon) + FFT/eigvals correctness
- **Device-routing performance audit + fix (the headline).** Benchmarked CPU vs Apple-Silicon MPS for every contract at its real production budget (end-to-end `fit()`, median of runs). The launch/scatter-bound contracts are FASTER on CPU and are now pinned there when the requested device is MPS: the relational family `graph`/`equivariant`/`set` (scatter/`index_add_` bound, ~4x -- already routed pre-2.1.0) PLUS the previously-unrouted dense `sequence` (recurrent per-timestep loops, ~1.7x), `4d` (the `conv4d` temporal-decomposition K_t loop, ~2.1x), and `volumetric` (small/depthwise `conv3d` at width 16, ~1.4x). `spatial` (dense conv2d, MPS ~5x) and `operator` STAY on MPS. NON-OBVIOUS operator finding: at the real width-24/depth-3 budget the operator contract is MPS-faster across 1D/2D/3D (1.2-5.2x) -- the FFT is matmul-dominated at that size (an earlier shallow-config test misleadingly showed operator-1D CPU-faster); routing it to CPU was rejected as it would be a 1.2-5.2x SLOWDOWN. Root cause of the CPU wins: MPS carries a ~0.25-0.5ms fixed kernel-launch overhead that dominates small/looped/scatter work.
- **New shared routing predicate.** `ilmarinen/device.py` gains `MPS_CPU_FASTER_CONTRACTS` (the frozenset above) and `prefer_cpu_on_mps(contract, device)`. It is MPS-GATED by construction (`str(device).startswith("mps")`) so CUDA is never forced to CPU -- on CUDA these same ops are fast and stay on the GPU. Wired into `AllGraph.fit()` as a post-routing pin (after `_resolve_contract`, downstream of the `self.device = self._base_device` reset so it can't become sticky across a reused instance, upstream of size-selection + deploy so every sub-fit and the final train inherit CPU); `_subfit_device` generalized from the relational-only whitelist to the same predicate.
- **`load()`/`predict()` routing gap (correctness + perf).** `AllGraph.load()` previously placed a reloaded model on the requested device with NO relational guard -- a graph/equivariant/set model saved and reloaded with the default `device='auto'` ran all `predict()` scatter on MPS (the exact ~15x path `fit()` routes around) and, with `PYTORCH_ENABLE_MPS_FALLBACK` unset, some relational ops (`index_reduce`, spline `searchsorted`) would HARD-RAISE rather than degrade. `load()` now reads the checkpoint's contract first and applies `prefer_cpu_on_mps` before moving the net, mirroring `fit()`; a reloaded model predicts on the device `fit()` would have chosen.
- **FFT/eigvals correctness on the GPU-resident paths.** Operator stays on MPS, so its three spectral closures (`_SpectralConv{1,2,3}d`, operator_schema.py) gained a `nan_to_num` guard on the returned field, mirroring the sequence spectral primitive's existing guard against MPS silently emitting non-finite `rfft`/`irfft` output (no-op on finite CPU/CUDA tensors, so numerics are bit-unchanged there). `neural_ode.leading_jacobian_re` now computes `torch.linalg.eigvals` on `J.cpu()` -- the non-Hermitian eig kernel is absent on MPS (would raise with fallback unset), and the matrix is tiny (<=18x18) so CPU is also faster. Routing `4d` to CPU incidentally removes the `conv4d` missing-kernel raise risk on MPS.
